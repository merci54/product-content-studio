- **Розробку вів разом із Claude Code:** визначав підхід (структура та рішення за зразком моїх проєктів), переглядав кожну частину коду перед додаванням у проєкт, перевіряв результат (типи, lint, тести, сценарії в браузері) і відхиляв або виправляв невдалі варіанти — наприклад, відмовився від редактора товару, який AI написав без мого контролю, і зібрав його заново частинами, розбираючи кожну.
- **Нове для мене** (SQL і Prisma, тести на Vitest і Playwright, CI): реалізовано разом із Claude Code, який пояснював концепції; паралельно вивчав теми за документацією та відео на YouTube.
- **Верстку та стилі** (Tailwind) робив Claude Code, а я перевіряв результат у браузері на десктопі й мобільному: верстати вручну немає сенсу, це лише забирає час. Демонстраційний вміст трьох товарів теж згенерований AI.
- **Документацію** (README.md і цей AI-WORKLOG) складав Claude Code за результатами роботи, а я перевіряв, доповнював і редагував текст.
- **На мені:** запуск і перевірка кожного кроку, рев'ю коду, ручна перевірка в браузері та Prisma Studio, усі коміти.

## Приклади рішень

### 1. E2E-тест виявив soft 404 для чернетки в production

**Проблема.** Під час розробки Claude Code перевіряв відповідь `404` для чернетки лише в dev-режимі. E2E-тест на production-збірці показав, що сторінка чернетки й неіснуючого товару віддає статус `200`. Причина — Cache Components у Next.js 16: заголовки надсилаються до виклику `notFound()`, тож статус уже не змінити.

**Рішення.** Вимкнути Cache Components: усі сторінки залежать від свіжих даних бази, тож кешування нічого не дає. Варіант на копії проєкту перевірив Claude Code.

**Перевірка.** Після виправлення чернетка й неіснуючий slug віддають `404`, тест «чернетка недоступна за прямим URL і через публічний API» проходить і тепер захищає від регресії.

```ts
const pageResponse = await page.goto('/products/llianyi-fartukh');
expect(pageResponse?.status()).toBe(404);
```

**Зміни:** [`a303828`](https://github.com/merci54/product-content-studio/commit/a303828)

### 2. `connection()` для каталогу в Next.js 16

**Проблема.** Claude Code звірився з документацією Next.js 16 у `node_modules` і знайшов, що запити через синхронний `better-sqlite3` виконуються під час збірки. Без виправлення каталог закешувався б, і щойно опублікований товар у ньому не з'явився б.

**Рішення.** Додати `await connection()` перед запитом до бази.

**Перевірка.** Змінював статус товару в Prisma Studio: після оновлення сторінки товар з'являвся в каталозі та зникав із нього. Зараз це покриває e2e-тест «опублікована чернетка з'являється в каталозі».

**Зміни:** [`38b923c`](https://github.com/merci54/product-content-studio/commit/38b923c), [`lib/products.ts`](lib/products.ts)

## Роль автотестів

- Автотести (25 unit і 13 e2e) створені разом із Claude Code і стали основним способом перевірки AI-коду. Саме e2e на production-збірці знайшли баг із прикладу 1, який ручна перевірка в dev пропустила.
- Тести запускаються в CI (GitHub Actions) на кожен push, тож регресії видно одразу.

**Оцінка якості тестів.** Щоб переконатися, що тести справді ловлять помилки, а не просто проходять, я вручну ламав код валідації (`lib/validation/product.ts`):

- `z.strictObject` → `z.object` (вимкнути захист від зайвих полів) — падає тест «відхиляє поля лише для перегляду: назву та характеристики»;
- видалити `.trim()` — падають 4 тести на порожні поля, поля з самих пробілів і обрізання пробілів.

Після повернення коду — знову 25 passed.

## Інші помітні моменти

- Claude Code запропонував застарілий тип `FormEvent`; я помітив закреслення в редакторі, тип замінено на `SubmitEvent`.
- Шрифт Geist був підключений лише з латиницею, тому український текст показувався шрифтом Arial. Замінено на системний шрифт (під час роботи зі skill `apple-design`).
- Тег `latest` у Prisma вказував на нестабільну `8.0.0-rc`, тому версію зафіксовано на `7.10.1`.
- Справжній пароль адміністратора в `.env.example` помічено до push і замінено на заглушку.
- Prisma Studio 7.10 не приймає URL `file:./dev.db`; причину знайдено в коді CLI, обхід — `--url "file://./dev.db"`.
- Перевірка свіжого клону показала, що падає `npm ci` і не генерується Prisma Client. Виправлено оновленням lock-файлу та скриптом `postinstall`.
- CI зроблено разом із Claude Code. Push workflow-файлу GitHub відхилив через відсутність права `workflow` у токені; вирішено через `gh auth refresh -s workflow`. Зміни: [`11710a9`](https://github.com/merci54/product-content-studio/commit/11710a9)
